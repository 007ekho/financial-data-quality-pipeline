# AWS Setup Guide

Complete step-by-step recreation of the AWS infrastructure for this pipeline. Run every command verbatim from your local terminal.

## What you'll build

- An S3 bucket for raw `.parquet` drops from the source system
- An SQS queue that Snowpipe subscribes to for file-arrival notifications
- An IAM role Snowflake assumes when reading from S3
- All managed as a single CloudFormation stack

## Prerequisites

- AWS CLI installed and configured (`aws configure`) with admin access to a target AWS account
- The Snowflake account ARN (we'll need it later — see "Get Snowflake account ARN" below)
- Region: this guide uses `eu-north-1`. Change if you prefer.

---

## Step 1 — Get Snowflake account ARN

Log into Snowflake and run:

```sql
SELECT SYSTEM$GET_AWS_SNS_IAM_POLICY('arn:aws:sns:eu-north-1:placeholder');
```

This will fail with an error message that **contains the Snowflake AWS account ID** for your region. You'll see something like:

```
Snowflake AWS IAM user: arn:aws:iam::123456789012:user/abc
```

Copy that ARN. We'll embed it in the IAM trust policy.

If the workflow is different in your Snowflake region, you can also find it by running:

```sql
DESC INTEGRATION dummy;
```

after creating any storage integration — the `STORAGE_AWS_IAM_USER_ARN` field shows it.

---

## Step 2 — Create the CloudFormation template

Create the file `cloudformation/step1_s3_sqs.yml` in your project root:

```yaml
AWSTemplateFormatVersion: '2010-09-09'
Description: >
  Step 1 — S3 raw bucket + SQS queue for Snowpipe auto-ingest,
  plus the IAM role Snowflake assumes to read S3.

Parameters:
  BucketName:
    Type: String
    Default: financial-data-quality-pipeline-prod-raw-ingest
    Description: Name of the S3 bucket that receives raw .parquet drops.

  SnowflakeAwsIamUserArn:
    Type: String
    Description: The Snowflake AWS IAM user ARN (from SYSTEM$GET_AWS_SNS_IAM_POLICY or DESC INTEGRATION).

  SnowflakeExternalId:
    Type: String
    Description: External ID generated by Snowflake for the storage integration (set after creating integration).
    Default: PLACEHOLDER_UPDATE_AFTER_INTEGRATION

Resources:

  RawIngestBucket:
    Type: AWS::S3::Bucket
    Properties:
      BucketName: !Ref BucketName
      VersioningConfiguration:
        Status: Enabled
      PublicAccessBlockConfiguration:
        BlockPublicAcls: true
        BlockPublicPolicy: true
        IgnorePublicAcls: true
        RestrictPublicBuckets: true

  SnowpipeQueue:
    Type: AWS::SQS::Queue
    Properties:
      QueueName: financial-dq-snowpipe-queue
      VisibilityTimeout: 60
      MessageRetentionPeriod: 86400

  SnowpipeQueuePolicy:
    Type: AWS::SQS::QueuePolicy
    Properties:
      Queues:
        - !Ref SnowpipeQueue
      PolicyDocument:
        Version: '2012-10-17'
        Statement:
          - Effect: Allow
            Principal:
              Service: s3.amazonaws.com
            Action: sqs:SendMessage
            Resource: !GetAtt SnowpipeQueue.Arn
            Condition:
              ArnLike:
                aws:SourceArn: !Sub 'arn:aws:s3:::${BucketName}'

  RawBucketNotification:
    Type: AWS::S3::Bucket
    DependsOn: SnowpipeQueuePolicy
    Properties:
      BucketName: !Ref BucketName
      NotificationConfiguration:
        QueueConfigurations:
          - Event: s3:ObjectCreated:*
            Queue: !GetAtt SnowpipeQueue.Arn
            Filter:
              S3Key:
                Rules:
                  - Name: prefix
                    Value: financial_transactions/
                  - Name: suffix
                    Value: .parquet

  SnowflakeS3ReadRole:
    Type: AWS::IAM::Role
    Properties:
      RoleName: financial-dq-snowflake-s3-read
      AssumeRolePolicyDocument:
        Version: '2012-10-17'
        Statement:
          - Effect: Allow
            Principal:
              AWS: !Ref SnowflakeAwsIamUserArn
            Action: sts:AssumeRole
            Condition:
              StringEquals:
                sts:ExternalId: !Ref SnowflakeExternalId
      Policies:
        - PolicyName: AllowS3ReadAndSqsConsume
          PolicyDocument:
            Version: '2012-10-17'
            Statement:
              - Effect: Allow
                Action:
                  - s3:GetObject
                  - s3:GetObjectVersion
                  - s3:ListBucket
                Resource:
                  - !Sub 'arn:aws:s3:::${BucketName}'
                  - !Sub 'arn:aws:s3:::${BucketName}/*'
              - Effect: Allow
                Action:
                  - sqs:ReceiveMessage
                  - sqs:DeleteMessage
                  - sqs:GetQueueAttributes
                Resource: !GetAtt SnowpipeQueue.Arn

Outputs:
  RawBucketName:
    Description: S3 bucket for raw drops
    Value: !Ref RawIngestBucket

  SnowpipeQueueArn:
    Description: SQS queue ARN — paste this into the Snowflake pipe definition
    Value: !GetAtt SnowpipeQueue.Arn

  SnowflakeS3ReadRoleArn:
    Description: IAM role ARN — paste this into the Snowflake storage integration
    Value: !GetAtt SnowflakeS3ReadRole.Arn
```

---

## Step 3 — Deploy the stack

```bash
aws cloudformation deploy \
  --template-file cloudformation/step1_s3_sqs.yml \
  --stack-name financial-dq-s3-sqs-prod \
  --region eu-north-1 \
  --capabilities CAPABILITY_NAMED_IAM \
  --parameter-overrides \
    SnowflakeAwsIamUserArn=arn:aws:iam::123456789012:user/abc \
    SnowflakeExternalId=PLACEHOLDER_UPDATE_AFTER_INTEGRATION
```

Replace `arn:aws:iam::123456789012:user/abc` with the ARN you copied in Step 1.

Watch for `CREATE_COMPLETE`:

```bash
aws cloudformation describe-stacks \
  --stack-name financial-dq-s3-sqs-prod \
  --region eu-north-1 \
  --query "Stacks[0].StackStatus"
```

---

## Step 4 — Capture the outputs

```bash
aws cloudformation describe-stacks \
  --stack-name financial-dq-s3-sqs-prod \
  --region eu-north-1 \
  --query "Stacks[0].Outputs"
```

Save three values — you'll need them in Snowflake setup:

- `RawBucketName` → e.g. `financial-data-quality-pipeline-prod-raw-ingest`
- `SnowpipeQueueArn` → e.g. `arn:aws:sqs:eu-north-1:707258693559:financial-dq-snowpipe-queue`
- `SnowflakeS3ReadRoleArn` → e.g. `arn:aws:iam::707258693559:role/financial-dq-snowflake-s3-read`

---

## Step 5 — Create Snowflake storage integration

In Snowflake (logged in as ACCOUNTADMIN):

```sql
USE ROLE ACCOUNTADMIN;

CREATE OR REPLACE STORAGE INTEGRATION financial_dq_s3_integration
  TYPE = EXTERNAL_STAGE
  STORAGE_PROVIDER = 'S3'
  ENABLED = TRUE
  STORAGE_AWS_ROLE_ARN = 'arn:aws:iam::707258693559:role/financial-dq-snowflake-s3-read'  -- paste from Step 4
  STORAGE_ALLOWED_LOCATIONS = ('s3://financial-data-quality-pipeline-prod-raw-ingest/');
```

Then describe the integration to get the actual external ID Snowflake generated:

```sql
DESC INTEGRATION financial_dq_s3_integration;
```

Find these two values in the output:

- `STORAGE_AWS_IAM_USER_ARN` — confirms the same ARN we used in CloudFormation
- `STORAGE_AWS_EXTERNAL_ID` — **copy this value**

---

## Step 6 — Update the CloudFormation stack with the real external ID

```bash
aws cloudformation update-stack \
  --stack-name financial-dq-s3-sqs-prod \
  --region eu-north-1 \
  --use-previous-template \
  --capabilities CAPABILITY_NAMED_IAM \
  --parameters \
    ParameterKey=BucketName,UsePreviousValue=true \
    ParameterKey=SnowflakeAwsIamUserArn,UsePreviousValue=true \
    ParameterKey=SnowflakeExternalId,ParameterValue=<paste-the-external-id-here>
```

Wait for `UPDATE_COMPLETE`. The IAM trust policy now requires Snowflake to send this exact external ID — preventing other accounts from assuming the role.

---

## Step 7 — Verify the integration works

In Snowflake:

```sql
USE ROLE ACCOUNTADMIN;
USE DATABASE FINANCIAL_DATA;
USE SCHEMA BRONZE;

CREATE OR REPLACE STAGE financial_dq_s3_stage
  URL = 's3://financial-data-quality-pipeline-prod-raw-ingest/financial_transactions/'
  STORAGE_INTEGRATION = financial_dq_s3_integration
  FILE_FORMAT = (TYPE = PARQUET);

LIST @financial_dq_s3_stage;
```

If the integration is configured correctly, the LIST command returns successfully (empty list is fine — no files yet). Errors here mean the IAM trust policy isn't matching.

## What you've now got

- S3 bucket receiving file uploads
- SQS queue receiving notifications when files land
- IAM role Snowflake can assume to read S3
- Snowflake storage integration pointed at the bucket
- An external stage Snowpipe can consume from

Next steps continue in `docs/SETUP_SNOWFLAKE.md` (Snowpipe, schemas, tables, alerts).

## Teardown

```bash
aws cloudformation delete-stack \
  --stack-name financial-dq-s3-sqs-prod \
  --region eu-north-1
```

The bucket must be **empty** first. Empty it:

```bash
aws s3 rm s3://financial-data-quality-pipeline-prod-raw-ingest --recursive --region eu-north-1
```
